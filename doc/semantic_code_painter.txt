1. INTRODUCTION                          *semantic_code_painter-introduction*

Renders the tag artifact produced by analysis-engine as background tints and
gutter signs, coloring code by intent (Logging, Error Handling, ...) instead
of by syntax.

The renderer reads a JSON artifact (`tags.json` by default) from the project
root, matches spans to buffer-relative paths, and applies extmarks.

Each file entry carries a content `hash`; when the buffer no longer matches it,
the renderer refuses to paint and warns (the artifact is stale). Regenerate the
artifact after edits.

==============================================================================
2. SETUP                                            *semantic_code_painter-setup*

Install the plugin, then call setup() (optional; defaults are used otherwise): >

  require("semantic_code_painter").setup({
    artifact = "tags.json",
    root_markers = { ".git" },
    auto_render = true,
    intentMeanings = {
      Logging = "CONCEAL",
      ErrorHandling = "SHOW",
      UNTAGGED = "SHOW",
    },
    resolve = {
      precedence = { "SHOW", "HIGHLIGHT", "IGNORE", "CONCEAL" },
      default = "SHOW",
    },
    rules = {
      CONCEAL = { conceal = { lines = true } },
      SHOW = { highlight = true },
      IGNORE = { ignore = true },
    },
    tags = {
      Logging = { bg = "#1f2d1f", priority = 10 },
      ErrorHandling = { bg = "#2d1f1f", priority = 50 },
    },
  })
<

Dev install with a plugin manager (rtp path): >

  { dir = "~/repos/semantic-code-painter/nvim-renderer", config = function()
      require("semantic_code_painter").setup({ auto_render = true })
    end }
<

3. COMMANDS                                      *semantic_code_painter-commands*

:SCPainterRender                                *:SCPainterRender*
    Render intent tags for the current buffer.

:SCPainterClear                                 *:SCPainterClear*
    Remove decorations from the current buffer.

:SCPainterToggle                                *:SCPainterToggle*
    Toggle decorations on the current buffer.

:SCPainterRefresh                               *:SCPainterRefresh*
    Drop the artifact cache and re-render.

:SCPainterInfo                                  *:SCPainterInfo*
    Show current configuration.

==============================================================================
4. CONFIGURATION                            *semantic_code_painter-configuration*

`artifact`        (string)  default: "tags.json"
    Artifact filename looked up at the project root.

`root_markers`    (table)   default: { ".git" }
    Markers used to locate the project root.

`root`            (string)  default: nil
    Explicit project root override (skips discovery).

`auto_render`     (boolean) default: false
    Render automatically on `BufReadPost`.

`expand_on_cursor` (boolean) default: true
    Reveal a vertically concealed block while the cursor is inside it.

`handlers`        (table)   default: { "color" }
    Default handlers applied to meanings/tags without an entry.

`intentMeanings`  (table)   default: Logging/ErrorHandling/UNTAGGED
    Client-side intent-to-meaning mapping. Change these to switch the meaning
    of an intent without regenerating the artifact.

`resolve`         (table)   default: precedence + default
    Merge an annotation's intent meanings into one effective meaning. The first
    meaning present in `precedence` wins.

`rules`           (table)   default: CONCEAL/SHOW/HIGHLIGHT/IGNORE rules
    Per-meaning rendering rule; see |semantic_code_painter-handlers|.

`tags`            (table)   default: {}
    Tag colors/icons/priority. Also the legacy per-tag fallback for artifacts
    without `intents`.

==============================================================================
5. HANDLERS                                        *semantic_code_painter-handlers*

How an annotation renders is decided by its client-resolved meaning (or its
legacy tag). The entry maps a handler name to its options; the presence of a
handler enables it. >

  require("semantic_code_painter").setup({
    rules = {
      CONCEAL = { conceal = { lines = true } },
      SHOW = { highlight = true },
      IGNORE = { ignore = { fg = "#555555" } },
    },
    tags = {
      Logging = { bg = "#1f2d1f", priority = 10 },
      ErrorHandling = { bg = "#2d1f1f", priority = 50 },
    },
  })
<

Handlers: >
  highlight background color from the chosen tag. opts: bg, color.
  ignore    dark-gray foreground. opts: fg, color.
  color     background tint + gutter sign. opts: bg, sign, icon.
  conceal   replace text with a char, or hide whole lines.
            opts: char (inline), lines (vertical).
<

The highlight color is taken from the highest-priority tag in the span's
`intents` (`tags[tag].priority`), falling back to the built-in palette.

A meaning/tag without an entry falls back to the top-level `handlers` list. A
handler may be set to `true` for defaults or `false` to disable it.

`conceal.lines = true` hides the span's lines entirely (no height), leaving the
next visible line; `char` alone replaces the span's text inline. `conceal` sets
the window's `conceallevel` to 2 when it is 0, and can be combined with `color`.

==============================================================================
6. API                                                *semantic_code_painter-api*

require("semantic_code_painter").setup(opts)   Merge configuration.
require("semantic_code_painter").render()      Render current buffer; returns
                                               the span count.
require("semantic_code_painter").clear()       Clear current buffer.
require("semantic_code_painter").toggle()      Toggle current buffer.
require("semantic_code_painter").refresh()     Reload artifact and re-render.
require("semantic_code_painter").reveal_block() Expand the concealed block
                                               under the cursor, if any.
